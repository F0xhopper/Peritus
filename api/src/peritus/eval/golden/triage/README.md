# Triage golden sets

A triage golden set is a list of **human** keep/drop decisions about the
*candidates* a real build's triage saw — title, URL and snippet, before anything
was fetched. It is what calibrates `FETCH_SCORE_FLOOR` and what shows whether a
triage change improved selection or only changed it.

Labels are cheap compared with screening labels: a candidate is three lines, and
150 of them take about an hour. Nothing in this directory is generated by a
model — a model-labelled set measures triage against a model.

## Making one

**1. Build with the ledger.** Every build since migration 029 writes one
`candidate_screenings` row per candidate triage saw, with the snippet it was
shown. Find the job id in the build log or `build_jobs`.

**2. Export a sample.**

```bash
# the most recent build of an expert, however it was run
python -m peritus.eval.triage export src/peritus/eval/golden/triage/thomism.json --expert thomism
# or one queued build job
python -m peritus.eval.triage export src/peritus/eval/golden/triage/thomism.json --job 53
```

Two thirds of the sample come from the band around the floor (triage score 3–8),
where the decision is in doubt. The export is deterministic, so two people
exporting the same job label the same candidates.

**3. Label.** For each candidate set `"keep": true` or `false` — *should a corpus
on this topic fetch this?* — and a one-line `"why"`. Judge the candidate from its
title, URL and snippet, as triage must. Do not look at `ledger_score` or
`ledger_outcome` while labelling. Unlabelled entries (`"keep": null`) are skipped.

**4. Score.**

```bash
python -m peritus.eval.triage run src/peritus/eval/golden/triage/thomism.json
python -m peritus.eval.triage run src/peritus/eval/golden/triage/thomism.json --floor 5.5
```

The report gives precision/recall of "would be fetched" against "keep" under the
current code, the same for what the build actually fetched (from the ledger), the
keep rate per score band, Spearman between score and label, and splits by source
type and discovery route. It lists any labelled drop that would be fetched with a
model score under 3 — the failure the fail-closed triage exists to prevent.
